# Security Policy

## Reporting

Do not open a public issue for suspected vulnerabilities, leaked credentials, or exposed personal data. Until a private GitHub security-advisory channel is configured, contact the repository owner privately and include only the minimum reproduction detail.

## Supported state

Only the latest `main` revision is supported during portfolio development.

## Data safety

- Use synthetic demo data only.
- Never include secrets, tracking tokens, contact details, or sensitive request descriptions in issues, logs, screenshots, or test fixtures.
- Revoke exposed credentials immediately and preserve an audit timeline.
- Security exceptions must have an owner, reason, expiry date, and remediation task.
